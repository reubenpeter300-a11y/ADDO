Date: 2026-11-13

## What was actually checked
- Opened and listed `ADDO_Manager_Premium_v2_SOURCE.zip`; archive is readable and contains `pubspec.yaml`, Dart source, and `codemagic.yaml`.
- Confirmed there is no `android/` directory, no Gradle wrapper, no APK, and no `pubspec.lock` in the archive. The Android project is expected to be generated by the Codemagic workflow.
- Checked the Codemagic YAML syntax successfully.
- Checked the declared Flutter/Dart SDK requirement (`>=3.3.0 <4.0.0`) and dependency declarations.
- Reviewed database migrations, sale/return accounting, stock adjustment, backup, login and key UI source.

## Corrections made in this review
1. Negative stock adjustments now reduce unbatched stock first and then reduce batch quantities, keeping medicine aggregate quantity and batch totals consistent.
2. Return-adjusted gross profit now removes the returned unit margin (`unit_price - unit_cost`) rather than incorrectly subtracting unit cost alone.
3. Dashboard sales and profit now account for returned quantities.
4. Partially returned sales are marked `partially_returned`; fully returned sales are marked `returned`.
5. Legacy-stock COGS in the older single-item sale method uses the medicine's stored cost price rather than a caller-provided cost.
6. Backup checkpoint uses `PRAGMA wal_checkpoint(TRUNCATE)` and checks the busy result before copying the database.
7. Codemagic logs Flutter, Flutter doctor and Java versions before package resolution, analysis and APK build.

## Important remaining defects / limitations
- The app still has default credentials (`admin` / `admin123`, PIN `1234`) on a fresh database. First-run mandatory credential setup is not implemented.
- Database and backups are not encrypted.
- Returned stock is added back to aggregate stock as legacy stock; there is no quarantine/inspection flow and no exact original batch allocation persisted per sale line. This should be fixed before operational use in a pharmacy.
- Supplier payments are tracked by supplier name, not allocated to invoice IDs.
- Reports are CSV, not native XLSX or PDF.
- No automated tests are included.
- No `android/` project or APK is present in the source ZIP; the CI workflow generates Android scaffolding on Codemagic.
